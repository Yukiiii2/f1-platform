# V2 Phase 1: Near-live Session Updates

**Goal:** Extend explicitly registered session updates with provisional incremental
REST refreshes, retaining V1 historical finalization and all provenance rules.

**Architecture:** Reuse the separate worker, its PostgreSQL connection lock, the
normalized telemetry importer, immutable raw revisions and observation ordering.
Keep live cursors and quality state on existing jobs. No new queue, transport,
provider-facing public API, frontend layout, dependency, or autonomous discovery.

**Authority:** The user's V2 Phase 1 requirements, AGENTS.md, current implementation,
ARCHITECTURE.md and DATA_AND_TELEMETRY.md. Do not commit or push.

## Decisions

- Registration opts into live updates; old jobs retain historical-only behavior.
- Active status requires source evidence, not elapsed schedules. Source session
  mapping, selected driver codes, season/type/country/date remain validated.
- Authenticate only live REST calls; renew provider tokens server-side. Credentials
  and upstream response errors never enter application responses or logs.
- Poll no faster than 60 seconds, retaining bounded provider pacing (historical 30/min,
  authenticated live 60/min). Timestamp streams use bounded windows and 120-second overlap; small
  mutable lap/stint/race-control snapshots are rechecked. Late/earlier missing data stays partial
  until a full historical refresh; finalization never uses an incremental bundle.
- Unchanged payloads do not rewrite normalized values or raw revisions. Their
  observation watermark advances to protect against delayed stale corrections.
- Persist successful live cursor advancement and provisional state atomically with
  import data. Interrupted workers repeat safely under the existing global lock.
- Three live failures suspend live polling, not post-session finalization. Operator
  retry can resume it. Historical retry budgets and settling/evidence remain intact.
- Session reads expose additive update quality metadata; the public update endpoint
  omits provider IDs, driver mappings, cursors, credentials and failure internals.
- Minimal reusable notice on race/telemetry/strategy pages offers manual refresh. Preserve
  selections and retry states. No automatic Pitwall calls or frontend polling.
- Provisional evidence remains explicitly provisional through Pitwall tools/answers.

## Operational limits

Live access requires a provider subscription configured by the operator. Initial
and delayed windows provide partial coverage; source corrections outside the
overlap are recovered by final full imports. REST worker throughput depends on
selected driver count and provider latency. UI refresh is explicit, not streaming.
